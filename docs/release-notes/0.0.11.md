## What's new

### Worktrees

- **`MERGED` means the worktree's own work reached its base.** A worktree
  brought up to date from its base (`u`, a fast-forward, a rebase or a reset)
  without a commit of its own no longer shows `MERGED`, and neither does one
  whose commits were thrown away.
- **Squash and rebase merges count as merged.** When every file a worktree's
  commits change is the same in its base, the card shows `MERGED`, `m` no
  longer offers to merge it again, and `clean N` removes it with the others.
- **`to merge` leaves out merge commits that brought the base in**, so
  updating with a merge commit no longer reads as work to merge back.

### History

- **Resize the commit list.** Drag the divider between the commit list and
  the commit's changes; double-click puts it back. The split is kept as a
  share of the window and saved with the appearance settings.

### Releases

- **A release is published after its pre-releases.** `0.0.10` was skipped
  by the release workflow because `0.0.10-rc.3` sorted after it.
