# 히스토리 검색 설계안

사용자는 커밋을 찾을 때 파일 경로, 메시지에 쓴 단어, 다른 곳에서 복사한 해시 중 하나를 기억한다. 히스토리 헤더의 기존 `Find ⌘F`를 이 세 경우의 진입점으로 쓴다. 파일을 고르면 **그 파일이 바뀐 이력**이 열리고, 메시지나 해시로 커밋을 고르면 **그 커밋이 그래프에서 선택**된다. 찾으려는 커밋이 현재 검색 범위에 있으면 로그를 미리 내려 보지 않고도 찾을 수 있다.

## 1. 어디에 무엇을 보여줄까

현재 Find는 HISTORY 패널 안에서 그래프 자리를 검색 결과에 내주고 입력창에 포커스를 둔다. 이 배치를 이어 쓴다. 검색 중에도 오른쪽 변경 파일과 diff는 마지막으로 선택한 커밋을 보여준다. 화살표로 후보 열 개를 훑어도 diff를 열 번 읽지 않는다. 행을 클릭하거나 ⏎로 확정할 때 상세 패널을 한 번 갱신한다.

**파일을 찾을 때** — 처음 열면 Files가 선택돼 있다. 기존 사용자는 곧바로 타이핑할 수 있다. 검색 대상은 기준 커밋의 트리이므로 헤더에 실제 기준을 표시한다. 전체 브랜치 그래프에서 열어도 파일 검색의 기준은 HEAD다.

```text
HISTORY
[■ Files] [□ Commits]   files at HEAD                  [×]
❯ search
› crates/gf-app/src/features/history/search.rs
  crates/gf-app/src/widgets/file_search.rs

2 files · ⇥ switch mode · ↑↓ move · ⏎ show file history
```

**커밋을 찾을 때** — Commits를 누르면 입력창은 같은 자리에 있고 범위 문구가 바뀐다. 제목만 보고 이유를 알기 어려운 결과에는 본문의 일치 구절을 보여준다. 아래는 develop에서 검색한 예다.

```text
HISTORY
[□ Files] [■ Commits]   commits on develop             [×]
❯ retry
› a83c721  Retry fetch after credentials expire
  90ef6c3  Recover an interrupted fetch
           …preserve the remote URL before retry…

2 commits · ⇥ switch mode · ↑↓ move · ⏎ show commit
```

Files와 Commits의 글자색을 통일하고 모드 선택 여부는 ■와 □로 표시한다. 행 왼쪽의 선택 표시와 행 배경을 함께 써서 현재 후보를 구분한다. 검색어와 일치한 부분에는 테마 강조색을 쓴다. 짧은 해시는 고정 폭 열에 두고 제목과 본문은 남는 너비 안에서 말줄임한다. 본문은 일치한 단어 주변을 잘라 한 줄만 쓴다. 좁은 패널에서는 하단 키 안내를 두 줄로 감싸며 입력창과 닫기 버튼을 우선 확보한다. 파일 행은 기존 한 줄 높이를 쓴다. 커밋 목록은 본문 미리보기가 필요한 결과가 있으면 목록 전체에 두 줄 높이를 적용해 스크롤과 키보드 이동의 행 높이를 일치시킨다.

## 2. 열기부터 돌아오기까지

| 사용자의 동작 | 화면과 포커스 |
|---|---|
| 히스토리의 Find 클릭 또는 ⌘F | 입력창에 커서를 둔다. 저장소 탭에서 처음 열면 Files, 이후에는 그 탭에서 마지막으로 쓴 모드로 연다. 새 검색어는 빈 문자열에서 시작한다. |
| 모드 이름 클릭 또는 검색 중 ⇥ / ⇧⇥ | Files와 Commits 사이를 전환한다. 입력한 문자열은 유지하고 입력창으로 포커스를 돌린다. 파일명으로 착각해 입력한 단어도 그대로 커밋에서 찾을 수 있다. |
| 타이핑·붙여넣기 | 결과가 도착하면 첫 행을 선택한다. 한글 조합을 확정하는 ⏎는 입력기가 먼저 소비한다. 검색 필드의 좌우 키와 편집 단축키는 텍스트 편집에 쓴다. |
| ↑↓ / Page Up·Down / Home·End | 현재 결과 안에서 선택과 스크롤을 함께 이동한다. 입력창에서 바로 이어서 타이핑할 수 있다. |
| 파일 행 클릭 또는 ⏎ | 검색을 닫고 해당 파일의 변경 이력을 연다. 기존 동작대로 해당 파일을 상세 패널에서 먼저 보여준다. 이력 헤더의 × 또는 Esc로 이전 이력으로 돌아간다. |
| 커밋 행 클릭 또는 ⏎ | 검색을 닫고 같은 범위의 그래프에서 해당 커밋을 선택해 화면 안으로 스크롤한다. 변경 파일과 diff는 일반 커밋 선택 흐름을 따른다. 이후 ↑↓는 그래프의 이웃 커밋으로 이동한다. |
| 선택 전에 × 또는 Esc | 검색을 닫고 열기 전 그래프의 선택·스크롤·히스토리 포커스를 복원한다. |
| 검색 중 범위 변경 | 변경한 범위를 헤더에 즉시 표시하고 같은 검색어로 다시 조회한다. 이전 범위에서 온 응답은 폐기한다. |

파일별 이력에서는 현재 Find 진입점이 숨겨진다. 이번 버전은 HEAD·전체 브랜치·브랜치·태그 화면에서 제공하며, 파일별 이력 안에서 다시 검색하는 흐름은 후속 범위로 둔다. 파일 뷰어와 blame에서 ⌘F는 계속 해당 파일의 텍스트를 찾는다. 툴팁과 `:help`에는 진입 위치별 동작을 적고 Windows의 키 안내는 기존 플랫폼 변환을 거친다.

## 3. 어떤 결과를 어떤 순서로 보여줄까

- **Files**는 기존 파일명·경로 매칭, 순위와 강조 표시를 재사용한다. 예전에 삭제된 파일은 기준 커밋의 트리에 없으므로 후보에 포함되지 않는다.
- **메시지**는 제목과 본문에서 대소문자를 무시하고 연속된 문자열을 찾는다. 예를 들어 `fix.*`를 입력하면 점과 별표까지 글자 그대로 찾는다. 앞뒤 공백은 제거하고 내부 공백은 보존한다.
- **해시**는 입력 전체가 16진수 4자리 이상이면 대소문자 구분 없이 전체 해시의 앞부분과 대조한다. `abc`는 메시지만 찾고 `abcd`는 두 검색을 함께 수행한다. 약식 해시가 여러 커밋에 걸치면 후보를 모두 선택 가능하게 보여준다. 표시된 짧은 해시가 서로 같으면 구분되는 자리까지 늘린다.
- **순서**는 해시 일치를 먼저 두고, 다음으로 메시지 일치를 둔다. 각 그룹 안에서는 현재 히스토리 순서를 따른다. 같은 커밋이 여러 조건을 만족하면 한 행만 쓴다. 제목에서 일치하면 제목을 강조하고, 본문에서만 일치하면 미리보기를 붙인다.
- **범위**는 현재 그래프가 보여주는 이력 전체다. 브랜치·태그는 해당 지점에서 도달 가능한 커밋을, 전체 브랜치는 그래프와 동일한 ref 집합을 사용한다. 검색을 시작하기 전에 로드한 행 수는 결과에 영향을 주지 않는다. 다른 브랜치에만 있는 해시를 입력해도 검색 범위가 저절로 바뀌지 않는다.

## 4. 기다림과 빈 화면

| 상태 | 보여줄 내용과 가능한 동작 |
|---|---|
| 빈 입력 | Files는 기존 초기 파일 목록을 표시한다. Commits는 `Type a commit message or at least 4 hash characters`를 표시하고 입력을 기다린다. |
| 첫 조회 중 | 결과 영역에 `Searching…`를 표시한다. 입력·모드 전환·닫기는 즉시 반응한다. |
| 같은 모드에서 다시 입력 | 이전 행은 흐리게 유지하고 하단에 `Searching…`를 표시한다. 새 응답 전에는 이전 행의 클릭·⏎를 막는다. 모드나 범위가 바뀌면 이전 행을 즉시 비운다. |
| 일치 없음 | 예를 들어 `No matching commits on develop`처럼 실제 검색 범위를 함께 보여준다. 파일 모드에서는 파일용 문구를 쓴다. |
| 결과가 많음 | 커밋은 최대 100건을 표시한다. 101번째 일치를 확인하면 `Showing first 100 commits · narrow your search`를 표시한다. 검사하지 않은 전체 건수는 추정하지 않는다. |
| 커밋이 없는 저장소 / 조회 오류 | 각각 `No commits yet` 또는 Git 오류와 `Retry`를 표시한다. 재시도는 현재 범위와 입력값을 사용한다. |
| 선택한 커밋이 멀리 있음 | 이미 읽은 행은 즉시 선택한다. 추가 로드가 기존 대량 로드 확인 기준을 넘으면 필요한 규모를 먼저 안내한다. 취소하면 입력값·후보 선택·스크롤을 복원한다. 조회 중 ref가 바뀌어 커밋이 사라졌으면 범위를 갱신하고 재검색할 수 있게 한다. |

## 5. 구현 순서와 검증

1. **검색 껍데기와 파일 모드.** `features/history/search.rs`의 입력·선택·가상 목록을 공통으로 쓰고, `find_file.rs`에는 파일 후보를 구하고 파일 이력을 여는 역할을 남긴다. 검색 모드, 상태별 문구, 행 높이와 활성화 동작을 주입한다. 먼저 기존 파일 검색의 ⌘F → 입력 → ⏎ → Esc 흐름을 회귀 테스트로 고정한다.
2. **범위를 받는 커밋 조회.** `gf-git`의 기존 `LogQuery`와 숨김 ref 규칙에서 검색 범위를 구성한다. 메시지 검색은 기존 CLI grep 경로를 바탕으로 고정 문자열 옵션을 검색 전용으로 적용한다. 해시는 현재 범위의 rev-list에서 접두어가 일치한 커밋만 골라 메시지 결과와 병합한다. 결과 상한은 두 경로를 합쳐 중복을 제거한 뒤 적용한다. 입력마다 모든 커밋 본문을 앱 메모리에 쌓지 않는다. 실제 백엔드 선택과 계약은 GIX_MIGRATION에 기록한다.
3. **연속 입력과 결과 선택.** 입력이 150ms 멈추면 백그라운드 조회를 시작한다. 저장소·범위·모드·요청 세대를 대조해 최신 응답만 반영하고, 입력이나 범위가 바뀌면 기존 작업을 취소한다. `app/reveal.rs`의 선택·스크롤과 대량 로드 확인을 재사용하되, 검색에서 진입할 때는 브랜치·태그 범위 안에서 행을 찾아 해당 목록을 늘린다. 기존 blame 이동은 별도로 회귀 검증한다.
4. **화면과 성능 확인.** 긴 제목·한글 본문·좁은 폭에서 줄 높이와 강조 위치를 확인한다. 큰 이력에서 일치가 드문 단어와 4자리 해시를 연속 입력하며 첫 결과 시간, 입력 지연, 취소 후 남은 조회를 측정한다. 100건과 150ms는 초기 설계값이며 측정 후 조정한다.

| 인수 시나리오 | 통과 조건 |
|---|---|
| develop의 첫 페이지 밖에 있고 한글 본문에만 검색어가 있는 커밋 | 본문 구절이 보이고, 선택 후 develop 그래프의 해당 행과 변경 파일이 열린다. |
| 같은 4자리 접두어의 커밋 둘과 그 문자열이 제목인 커밋 하나 | 해시 후보 둘이 먼저 나오고 각각 식별된다. 해시와 제목이 함께 일치한 커밋도 한 번만 나온다. |
| 태그 범위 밖의 유효한 전체 해시 | 결과 없음에 태그 이름이 표시되고 그래프 범위와 선택을 유지한다. |
| 입력 직후 모드 변경·닫기·저장소 탭 전환 | 늦은 응답이 다른 결과를 덮지 않는다. 대기 중 ⏎를 눌러도 이전 결과가 열리지 않는다. |
| 파일 검색으로 이력 열기 / 커밋 검색 도중 취소 | 전자는 지정한 파일 이력을 열고, 후자는 처음의 그래프 위치로 돌아간다. |
| 키보드만 사용 / 마우스만 사용 | 두 방식 모두 열기, 모드 전환, 결과 선택, 취소까지 가능하다. 실제 앱에서 확인하고 툴팁과 도움말의 키 표기를 대조한다. |

구현 완료 기준은 위 시나리오와 새 로직 테스트, `cargo fmt`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace` 통과다.
